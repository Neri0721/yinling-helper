## 三、字段规范（JSONL 每行一个块）

```json
{
  "id": "5fe6d1d520cb-c0",
  "title": "人体真的需要定期排毒吗？",
  "content": "标题\n正文片段",
  "metadata": {
    "url": "https://www.piyao.org.cn/...",
    "tier": "official",              // official | dataset | media
    "tier_label": "官方原文",         // 供前端直接展示
    "date": "2026-10",               // 文章发布日期
    "domain": "健康",                // 健康 | 钱财 | 政策 | 儿童 | 其他
    "elder": 2,                      // 银龄相关度 0-3，用于排序不是过滤
    "source_name": "中国互联网联合辟谣平台",
    "retrieved_at": "2026-11-03",
    "chunk": 0,                      // 长文切分序号
    "chars": 386
  }
}
```

**关键约束**：

- `tier` 的取值不要改，`server.py` 的降级逻辑依赖 `official` / `dataset` 这两个值；
- `elder` 只用于排序（优先展示高分的），**不要用它过滤**——政策类内容往往没写"老人"二字，但老人最需要；
- 引用展示时，`source_name + date + url` 三个一起给，缺一个说服力就掉。

## 四、怎么重新生成（顺序不能反）

```bash
python tools/refetch_official.py      # 1. 回抓官方正文（慢，约 1 分钟）
python tools/filter_elderly.py        # 2. 生成银龄子集 kb_elderly.json
python tools/prep_kb.py kb_elderly.json   # 3. 生成子集导入包
python tools/prep_kb.py               # 4. 生成全量导入包
python tools/gen_testset.py           # 5. 生成 20 条召回测试题
python tools/recall_test.py           # 6. 跑召回基线
```

`prep_kb.py` 支持指定输入文件，输出前缀会自动跟随（`kb_elderly.json` → `kb_import_elderly.*`）。

## 六、已知问题（按优先级）

1. **官方只有 107 篇**。撑不起"可追溯到官方原文"的完整叙事。补法见第七节。
2. **钱财/诈骗样本只有 99 块**，而这是老人最高频受骗的场景。建议用规则引擎（`server.py` 的 `DANGER_WORDS`）兜底，不依赖语料。
3. **合集页未拆分**。官方有些条目是"今日辟谣｜A、B、C"的合集，一条里塞了三四个谣言，检索命中后返回的证据不够聚焦。可以按"？"或编号再拆一层。
4. **domain 分类是关键词硬匹配**，"其他"占比高是正常的，不必强行消掉。
5. `kb.json` 与 `kb_elderly.json` 存在冗余（子集是全覆盖真子集的拷贝），改动源数据后必须两边都重新生成。

## 七、补官方数据的正确姿势

官方站（piyao.org.cn）的列表页是 JS 渲染的，**脚本翻不到分页**，所以自动批量爬这条路已被验证走不通。

可行做法（半自动）：

1. 人工在浏览器里翻栏目页，把文章链接复制到一个文本文件，一行一个；
2. 跑 `python tools/fetch_official.py --urls urls.txt`，它会批量抓正文、清洗、按 URL 去重后入库；
3. 再按第四节重新生成导入包。

建议补充方向，按优先级：**政策补贴类**（人社、医保、地方公告）> **养老诈骗类** > **健康养生类**。
